# MCP і підключення систем

**MCP** (Model Context Protocol) дає агенту «руки» до зовнішніх систем (пошта, чати, Jira, HR). Без підключення модель або вигадує, або повзає лише браузером.

Клієнт MCP (наприклад Cursor) підключає модель до файлів, API й інструментів — так «розширюється пам’ять» і можливості агента.

## Детальніше

### Чекліст
1. Ключі локально (`workspace/keys/` тощо) — **не в git**.
2. MCP auth OK у Cursor Settings.
3. Read-only smoke-test: «перелічи X» / «покажи мій профіль».
4. Offline → скопіюйте текст помилки агенту, не «просто не працює».

### Безпека
Не комітьте секрети. Не лишайте паролі в чаті «назавжди». Для делікатних дій — human-in-the-loop. Де саме тримати ключі — див. розділ про паролі й секрети.

### Не підключайте зоопарк одразу
Кожен tool їсть опис у контекстному вікні. Почніть з 1–3 критичних підключень під вашу роль. Див. також розділ про Tools, Resources, Prompts і правила MCP.
