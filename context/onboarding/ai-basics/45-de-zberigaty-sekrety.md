# Де зберігати паролі й секрети

AI-агенту часто потрібен доступ до систем. Це **не** привід писати паролі в чат «назавжди» або класти ключі в git «щоб усім було зручно».

Коротке правило: **секрети — у сейфі, не в зошиті з знаннями.**

## Детальніше

### Добре (від надійнішого до «на крайній випадок»)
1. **Менеджер паролів у браузері** (або окремий: 1Password, Bitwarden тощо) — логіни до сайтів, які відкриваєте ви або браузер агента після вашого логіну.
2. **Системний Keychain / зв’язка ключів** (macOS) чи аналог ОС — для локальних секретів і сертифікатів.
3. **Локальні файли `.env` / `keys/`** на вашому комп’ютері — для API-ключів, токенів MCP, службових паролів. Файл читає скрипт або агент локально.

### Погано
- пароль або токен у повідомленні чату «про всяк випадок»;
- секрет у markdown-статті, skill або правилі, яке пушиться в git;
- один спільний `.env` у репозиторії «для команди» без окремого захищеного сховища;
- скріншот із паролем у Teams / Telegram.

### Практичний ритуал
1. Створили ключ у сервісі → одразу в менеджер паролів або локальний key-файл.
2. У репозиторії — лише приклад без секретів (на кшталт `.env.example` з порожніми полями).
3. Перевірте `.gitignore`: `keys/`, `.env`, сесії браузера — **не комітяться**.
4. Агенту кажіть *де взяти* секрет («прочитай локальний ключ»), а не *який він*.

### Якщо агент просить пароль у чаті
Зупиніться. Залогіньтесь самі в браузері агента або підставте секрет через безпечне локальне сховище. Human-in-the-loop тут — норма, не слабкість.
