# JSON і YAML: попередньо «утискати»

Якщо агенту потрібні не вся структура, а ~10% полів — виріжте їх скриптом у компактний текст / slim Markdown **перед** аналізом. Економія контексту й менше шансів, що модель пропустить важливе через обсяг.

Для «тонкого» шару даних часто зручніший **YAML** (або вже slim JSON): менше дужок і шуму, людині й моделі легше читати ті самі поля. Raw JSON/лог лишайте у файлі; у чат або в промпт — лише стиснутий вигляд.

## Детальніше

### Що обрати для slim
- **Slim JSON** — коли далі знову парсить скрипт або API чекає JSON.
- **YAML** — коли slim читає людина або LLM як текст (звіти, витяги, конфіги з кількома полями).
- **Короткий Markdown / таблиця** — коли важливі лише рядки «ключ → значення», без вкладеності.

У skill пропишіть: «не аналізуй raw, лише slim (JSON або YAML)». Raw — у файлі; slim — вхід для LLM. Це дешевше й стабільніше за будь-який Fast.
