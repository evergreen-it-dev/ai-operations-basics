# Які моделі обирати

| Задача | Вибір |
|--------|--------|
| Новий skill, розбір помилок, архітектура | Smart / сильніша (Grok, Sonnet…) |
| Звичайна робота за готовим skill | Звичайна / smart |
| Дебаг «чому раз 1 ≠ раз 2» | Тимчасово підняти розумність (Thinking за потреби) |
| Чиста механіка (шаблон, конвертація) | **Скрипт**, не модель |

**Не вмикайте Fast без потреби.** У білінгу Fast часто **×1.5–×6 дорожчий** за звичайну/smart модель — це **паливо токенів**, а не економія. «Швидше» ≠ «дешевше».

Механіку (шаблони, конвертації, утискання JSON) виносьте в **скрипти**, а не в «швидшу» модель.

## Детальніше

### Типові помилки
1. Завжди Thinking «про всяк випадок» — довго, дорого, інколи ускладнює просте.
2. Fast за замовчуванням «щоб зекономити / прискорити» — часто **дорожче** ×1.5–×6.
3. LLM на чистій конвертації CSV↔JSON — краще скрипт.
4. Одна і та сама «найрозумніша» модель на всі запуски skill — надмірно.

### Ритуал вибору
1. Проєктування skill / нова постановка — smart (або короткий Thinking, якщо плутається).
2. Щоденний запуск готового skill — smart/звичайна **або** скрипт для механіки.
3. Регрес / «інший результат» — smart + порівняння двох прогонів + пояснення відхилення.
4. Fast — **лише** після свідомого заміру вигоди (час і $), інакше вимкнути.

### Зв’язок із Deep Research
Deep Research — не «ще одна швидка модель», а режим глибокого занурення. Для своїх файлів — без web search. Див. розділ про Fast, Thinking і Deep Research.
