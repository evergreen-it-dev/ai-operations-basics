# Mermaid flowchart у Markdown (v2)

Перед генерацією або правкою будь-якого блоку ` ```mermaid ` у `.md` **перечитай повну специфікацію**: **[mermaid-tool-v2.md](mermaid-tool-v2.md)** (золоті правила, шаблони, анти-патерни, формат виводу).

## Швидкий чеклист (не замінює reference)

1. Перший рядок блоку (обовʼязково): `%%{init: {'flowchart': {'htmlLabels': false}} }%%`
2. Далі: `flowchart TD` або за потреби `flowchart LR` (інші орієнтації — лише якщо явно потрібно).
3. **Жодних пробілів/табів на початку рядків** всередині блоку `mermaid`.
4. **Усі видимі підписи з пробілами, кирилицею або спецсимволами — у подвійних лапках** `"..."`.
5. **Не починайте** підписи з `1.`, `2)` тощо; не використовуйте `end` як node ID (лише `EndNode`, `END`, `"end"` у лапках).
6. Node ID не починати з `o` чи `x` без обхідного прийому (`OTask`, `" oTask"`).
7. **Без порожніх рядків** усередині блоку.
8. **Не використовувати** `style` / `classDef`.
9. Блок **завжди закривати** окремим рядком ` ``` `.
10. У цьому контексті — **лише flowchart** (не sequence/state тощо), якщо користувач явно не попросив інше й середовище це підтримує.

## Формат відповіді агента

- Якщо потрібна лише діаграма: один fenced-блок ` ```mermaid ` … ` ``` ` без зайвого prose навколо (або мінімум пояснень за запитом користувача).
- Якщо діаграма частина документа — вставляти блок з дотриманням усіх правил з reference.

## Експорт у PDF

Щоб зібрати `.md` з цими діаграмами в **PDF** без втрати Mermaid, використовуй skill **`md-mermaid-pdf`** і скрипт `tools/markdown/mermaid_md_to_pdf.py`.
