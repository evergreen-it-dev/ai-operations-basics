# Joke Engineering — діагностика (reference)

**Принцип:** гумор = створення й розвʼязання зʼєднань між концептами/рамками. Коли не летить — одна або кілька властивостей системи зміщені.

## Дев'ять властивостей

| Властивість | Коли ламається |
|-------------|----------------|
| Connection distance | Занадто очевидно або занадто obscure |
| Connection density | Один thread — «тонко» |
| Resolution satisfaction | Punchline форсований / нелогічний |
| Specificity | Generic деталі |
| Irony layering | Плоска іронія |
| Audience co-creation | Over-explained — нема «aha» |
| Compression | Довгий setup, низький connection/words |
| Connection resilience | Потрібна вузька доменна knowledge |
| Authenticity | Не в голосі автора |

## Діагностичні стани

| Стан | Симптоми | Інтервенція |
|------|----------|-------------|
| **H1 Too obvious** | Бачиш punchline здалеку | Збільш distance, збережи coherence |
| **H2 Too obscure** | Не «доходить» | Scaffolding (контекст), не explanation |
| **H3 Low density** | Тонко, один зʼєднувач | Circular irony, nested absurdity, dual role |
| **H4 Over-explained** | Punchline проговорений | Strategic omission |
| **H5 Forced voice** | Не звучить як автор | Перепис під natural voice |
| **H6 Compression bloat** | Setup довгий | Прибрати те, що не будує connection |

## Типи зʼєднань

Contradiction · Frame shift · Bisociation · Pattern violation · Implicit connection

## Irony gradient (шаблон)

Великі зусилля → низька важливість · Точність → не та ціль · Ідеальне виконання → непотрібна задача

## Приклад трансформації

**Було (H3+H6):** «Boomers who limited kids' screen time now rot on cable news.»

**Стало:** role reversal + circular irony + конкретика («3am», «childproof news app») + implicit (який канал — доповнює аудиторія).

## Що skill не верифікує

Чи реально засмішить live-аудиторію — лише людина. Skill дає структурну діагностику й перепис.
